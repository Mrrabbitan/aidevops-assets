# 外部系统接入预留与联调边界

本工程已提供资产域、版本化配置、执行队列、权限、审计和明确标识的模拟闭环。真实云平台、学校身份、流水线、制品仓库、监控和通知服务需要按本文件补充适配代码及现场联调。仅保存 URL 或凭据引用，不会启动真实操作；`REAL` 当前返回 `NOT_CONFIGURED` / `ADAPTER_NOT_CONFIGURED`。

## 1. 当前已有的代码边界

| 接入方向 | 当前入口/实现 | 真实联调需要补充 |
| --- | --- | --- |
| 学校身份 | Spring Security OIDC JWT，前端授权码 + PKCE；`OIDC_ISSUER`、`OIDC_JWKS`、前端 `VITE_OIDC_*` | 对方 issuer/JWKS/audience、用户唯一 sub、回调域、退出和令牌续期；首次项目授权；组织映射另行实现 |
| 资产发现/清单同步 | `AssetService.discover/syncPreview`、`CollectionScheduleService`；fixture 仅 demo | 按连接器/网络/对象范围调用对方清单接口，外部稳定 ID、分页完整性、来源时间、字段映射与差异预览 |
| PVE/K8S/环境/部署/分发 | `TaskExecutionAdapter`、`UnconfiguredTaskAdapter`、任务类别配置、独立 worker | 认证解析、能力探测、协议调用、外部操作 ID、逐目标状态核查、幂等/恢复和回退 |
| 制品与流水线 | 任务配置保存 `artifact`、`artifactDigest`、版本和依赖 | 权威系统引用解析、摘要与签名验证、流水线启动/查询、构建及发布回执；不另建制品仓库 |
| 监控 | `POST /api/v1/observations`、新鲜度/乱序/去重与规则判断 | 采集器授权、设备映射、单位/时间标准化、故障重连；不得用查询失败生成正常样本 |
| 外部通知 | `AlertService` 持久通知/回执；`IN_APP` 可用，EMAIL/WEBHOOK 未配置 | 真实发送适配、对方受理 ID、重试/限流及送达证据；受理与送达分别记录 |
| 连接设置 | `GET /connections`、`PUT /connections/{id}`、`POST /connections/{id}/test` | 当前预置连接配置可维护；真实连通测试及新连接注册流程需要适配实现 |

这些方向并非都已有可直接插拔的 Java SPI。目前明确的执行 SPI 是 `TaskExecutionAdapter`；发现、同步和通知预留在对应领域服务中，后续应抽取其专用接口，而不是绕过服务直接改表。`AssetsPort` 是任务域读取资产的内部边界，不是外部云资源 SDK。

## 2. 连接和凭据契约

连接记录包含项目、类型、`mode`、`endpoint`、`credentialRef`、`enabled` 和 `version`。端点仅允许不含 URL 用户信息的 HTTP/HTTPS 地址；凭据字段只保存引用。客户端不得提交 access token、password、private key、kubeconfig 等明文进入任务配置、日志或快照。后续由服务端凭据解析器按现场方式读取密钥管理系统或受控环境变量；当前没有已经工作的通用密钥托管服务。

开发示例可使用 `https://pve.example.invalid`、`env:PVE_TOKEN` 等明确的占位地址/引用。外部端点应由运维受控配置和允许范围校验，不能把用户任意 URL 当作可执行调用目标。真实凭据及学校内部地址不应进入 public 仓库。

启用连接并不等于启用适配器。当前连接测试对真实模式仍返回 `NOT_CONFIGURED`，不会模拟真实已连通；适配完成后应区分未配置、认证失败、不可达、能力不支持和连通成功，并保留核查时间及对方版本。

## 3. 真实任务适配实施要求

`TaskExecutionAdapter` 当前方法为 `supports(mode)` 与 `execute(run, target)`，传入冻结运行及单个目标，返回持久化结果对象。模拟实现只支持 `SIMULATED`；未配置实现对 `REAL` 拒绝执行。真实接入不能只新增一个类就宣称完成：`TaskService.enqueue` 目前还显式拒绝 REAL，恢复核查也必须接入实际探测。需要在完备的能力配置和契约测试通过后，受控替换这些拒绝分支。

真实适配器应按任务 `kind/type` 路由，不要同时注册多个仅返回 `supports("REAL")=true` 的实现而产生歧义。首次可以使用一个 REAL 分发适配器，再按 PVE/K8S、环境、部署、客户端等协议拆分内部实现。

每次外部操作至少保留下列证据，具体结果 schema 应在联调时冻结：

| 内容 | 含义 |
| --- | --- |
| `connectorId`、外部目标 ID | 连接器与稳定资源身份，不使用显示名称唯一匹配 |
| 外部操作 ID | 对方创建/发布/分发请求的可追踪标识，崩溃后可核查 |
| 配置摘要/版本 | 对应当前不可变输入快照和已确认计划 |
| 阶段与结果 | 区分请求受理、实际运行、目标就绪和最终失败 |
| 时间与证据引用 | 请求/受理/完成/最后核查时间、脱敏回执或日志引用 |
| 前一版本/回退证据 | 能明确核对回退后实际版本，不仅保存“已回退”文案 |

在提交有副作用操作前先建立可持久化的外部关联，使用对方支持的幂等标识。连接超时或 worker 租约丢失后，先按外部操作 ID 查询；状态不明保持 `UNKNOWN`，不盲目再次创建。旧 worker 必须继续受本地 fencing token 约束。逐目标成功不能由“提交 API 返回 200”推定，资源真正可用/客户端更新完成应有相应证据。

生产操作仍经过冻结确认与项目权限，真实适配不能增加后台绕过入口；worker 在执行前及逐目标执行前核查当前授权。服务重启后跳过积压周期，UNKNOWN 运行必须先核查。

## 4. 发现、同步和监控映射

采集以项目、连接器、模式和外部资源 ID 建立稳定映射，IP 另按网络范围检查。每次清单必须记录采集时间、来源版本、范围、分页是否完整以及字段已知/未知状态。来源未返回的资源不能直接视为已删除；未知值不能覆盖人工已核实字段。

发现产生候选，入库是独立人工确认。同步先保存差异及资产版本，后续由授权人员确认；周期采集的同步结果仍为 `PREVIEW_READY`，不可改成无审核直接覆盖。真实发现和同步适配应加入外部身份重复、字段冲突、部分分页失败、旧预览提交、来源时间倒退等测试。

监控接入使用 `POST /observations`，以独立主体授予目标项目的 `observation.write`；入口不是匿名 webhook。每条事件带 `externalEventId`、资产 ID、模式、真实采样时间和标准化指标。当前新鲜度窗为 300 秒，过期、无指标、查询失败不得作为正常健康。真实指标只能关联 REAL 资产，模拟观测不能写入真实对象。规则处置状态和观测恢复事实分别记录。

## 5. 建议的逐接口联调记录

每个适配器完成后在交付记录中标明四项状态：**业务已实现、适配代码已实现、模拟验证通过、真实联调通过/待完成**。不要仅因本地模拟成功标记真实通过。

联调记录至少覆盖：对方名称与版本、受控环境/范围、已授权服务主体、认证方式、字段/单位映射、正常请求、权限不足、重复请求、超时、部分失败、乱序回执、worker 中断后的核查、生产确认变更和回退。保存脱敏证据及外部操作 ID；真实凭据另行受控交接。

当前没有新增学校服务地址、PVE/K8S 凭据、生产流水线或通知账号，也没有执行真实资源变更。正式性能、容量、国产环境和实际设备兼容验证仍需在冻结的现场环境中完成。
